# tw-realestate-checklists｜不動產檢查表工具箱

## 這是什麼

三個不動產工作上常用的「檢查表／工作表」，做成一個免安裝的小網站：

- **預售屋買賣契約檢查表**：對照應記載事項，一條一條勾「已確認／有問題／不適用」，自動整理出有問題的條文。
- **農舍興建資格自我檢查**：回答申請人、土地、建築規模的問題，得到「看起來符合／需要再確認／可能不符合」和理由。
- **物件介紹四大性質工作表**：照「使用性、機能性、建設性、未來性」填重點，一鍵產生 LINE 短版、FB 長版、帶看說明條列。

免安裝、免伺服器、不用網路：雙擊 `index.html` 就能用。你填的資料只存在你這台電腦的瀏覽器。

線上試用：https://larryveryhandsome.github.io/tw-realestate-checklists/

---

## 適合誰

- **買方**：簽預售屋合約前，自己對一遍有沒有常見的不合規寫法。
- **代書（地政士）**：審約時當作檢查清單，有問題的條文附備註，直接列印給客戶。
- **房仲**：寫物件介紹文、準備帶看說詞；接到農地物件時先幫屋主做初步評估。
- **地主**：想在自己的農地蓋農舍，先看看大概卡在哪一關，再去問縣市政府。

## 5 分鐘開始

1. 下載這個專案（綠色 **Code** 按鈕 → **Download ZIP**），解壓縮。
2. 雙擊 **`index.html`**，選一個工具。
3. 開始填。資料會自動存在瀏覽器裡，關掉再開還在（無痕模式除外）。
4. 要給別人看：按 **列印／存 PDF**。
5. 要換電腦或備份（預售屋檢查表）：按 **匯出 JSON**，到另一台電腦按 **匯入 JSON**。

## 三個工具說明

### 1. 預售屋買賣契約檢查表（`presale.html`）

- 依應記載事項點次分區（五、共有部分項目 …… 二十四、違約之處罰、當事人及基本資料），共 90 多項。
- 每一項寫的是「契約應該長這樣」，對照後選 **已確認／有問題／不適用**，再按一次可取消；每項都可寫備註。
- 每個區塊顯示進度，最上方彙整所有「有問題」的項目與備註。
- 可搜尋關鍵字（例如「交屋保留款」）、只看未檢查的項目。
- 列印時會自動展開全部區塊，印出每一項的結果與備註。

> 整理自地方政府公布之預售屋契約常見錯誤樣態，並對照內政部《預售屋買賣定型化契約應記載及不得記載事項》；原則上以主管機關最新公告為準。

### 2. 農舍興建資格自我檢查（`farmhouse.html`）

- 三組問題：**申請人資格**（農民資格、年齡、設籍、所有權、名下農舍）、**土地條件**（取得年數、面積、農用、經營實績、一地一舍）、**建築規模**（建蔽率、總樓地板面積、樓層與高度）。
- 面積可用平方公尺、公頃或坪填寫，會自動換算。
- 結果分三種：**看起來符合／需要再確認／可能不符合**，每一項都附理由。
- 判斷原則：
  - 沒回答或不確定 → 需要再確認。
  - 維護者不確定是否仍為現行規定的門檻（例如年齡、都市計畫區的數值） → 最多只會顯示「需要再確認」，不會判「可能不符合」。
  - 2000 年 1 月 28 日以前取得的農地、集村農舍 → 規定不同，一律「需要再確認」。
- 原則上僅供初步自我檢查，**請以地方主管機關（縣市政府）審查為準**。

### 3. 物件介紹四大性質工作表（`pitch.html`）

| 性質 | 重點 | 例如 |
|---|---|---|
| 使用性 | 物件本身的空間與使用狀況 | 坪數、格局、適合對象、土地用途 |
| 機能性 | 周邊現有的生活機能 | 超市、市場、學校、公家機關 |
| 建設性 | 區域目前的建設與交通 | 車站、道路、進行中的建設 |
| 未來性 | 區域未來的發展潛力 | 規劃中的重大建設、新交通路線 |

- 每個欄位都有範例提示；完整度條顯示填了多少、還建議補哪些。
- 自動產生三種格式：**LINE 短版**（每項自動截短）、**FB／社群長版**、**帶看說明條列**（照帶看順序排，附帶看前提醒），按「複製這一版」貼上即可。
- 沒填的欄位整行略過，不會出現空白標題。
- 可存多份草稿（存在瀏覽器），也可列印三種版本。

## 資料怎麼更新（法規改了改哪個檔）

| 要改什麼 | 改哪個檔 | 注意 |
|---|---|---|
| 預售屋檢查項目 | `js/data-presale.js` | 可改 `text`／`hint` 或新增項目；**不要改舊項目的 `id`**，否則使用者存的結果會對不上。改完更新 `lastChecked`。 |
| 農舍門檻值 | `js/data-farmhouse.js` 的 `thresholds` | 改 `value`；已對照現行條文的設 `certain: true`，不確定的設 `false`（只會顯示需要再確認）。改完更新 `lawVersion`、`lastChecked`。 |
| 農舍問卷題目、結果頁提醒 | `js/data-farmhouse.js` 的 `questions`、`reminders` | 新增題目時，判斷邏輯在 `js/core.js` 的 `evaluateFarmhouse`。 |
| 物件介紹欄位與文案格式 | `js/core.js` 的 `PITCH_FIELDS`、`generatePitch` | |

用記事本就能改；改完重新整理網頁即可。建議改完跑一次 `npm test`。

## 給開發者

```
index.html            工具箱首頁
presale.html          預售屋買賣契約檢查表
farmhouse.html        農舍興建資格自我檢查
pitch.html            物件介紹四大性質工作表
css/style.css         樣式（深色模式、列印、手機 375px）
js/core.js            核心（純函式，UMD）：進度、匯入驗證、農舍判斷、介紹文產生、跳脫
js/data-presale.js    預售屋檢查項目（設定 window.PRESALE_DATA）
js/data-farmhouse.js  農舍門檻與問卷（設定 window.FARMHOUSE_RULES）
js/app-common.js      共用畫面工具（localStorage 包 try/catch、下載、複製）
js/app-*.js           各頁畫面邏輯
tests/                單元測試（node:test，不用裝任何套件）
docs/金鑰申請.md       說明不需要金鑰
```

- 不用 CDN、不發任何網路請求；資料放在 js 檔設定全域變數，所以用 `file://` 雙擊也能讀到（不用 fetch）。
- 匯入的 JSON 會先驗證，格式不對整份拒絕；畫面上的文字一律先跳脫再放進 HTML。

```bash
npm test
```

需要 Node.js 18 以上。
